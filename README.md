## About me

I design and build the backends behind real-time multiplayer games and Web3 products: servers that stay correct across multiple instances when there are races, retries and dropped connections. Most of my work lives in private client and company repositories, so this page sums it up.

- **Distributed state:** Redis-backed services where every state change is an atomic Lua script, with instances holding no state of their own
- **Correctness under failure:** idempotent writes, state machines on every layer, append-only ledgers and refunds that reverse cleanly
- **Server-authoritative gameplay:** the server owns turn timers, reconnect windows and seat binding, and players never choose their own identity
- **Data-driven design:** rules engines and catalogs configured from an admin dashboard, so changes ship without a deploy
